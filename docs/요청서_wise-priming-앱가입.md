# 요청서 — Priming 앱 안 회원가입 + 가입 코드로 사용 기간 자동 부여 (2026-10-23)

보내는 곳: Priming 세션(`D:\Priming`) → 받는 곳: wise-priming 세션(`D:\wise-priming`). 로이 결정(2026-10-23).

## 왜
- 지금은 구글로 가입한 회원이 사이트 「내 기기」에서 **앱 비밀번호를 따로 정해야** 앱에 들어올 수 있다 — 불편하다(로이).
- 앱 로그인 화면에서 **바로 가입(이메일 + 비밀번호)** 하고, 입금 확인한 회원에게 준 **가입 코드**를 넣으면 **그 코드에 정해진 기간만큼 사용권한(`priming-app` 수강 등록)이 자동으로 붙게** 하고 싶다.
- 코드가 없으면 계정만 만들어지고 `not_member`(이용 불가) 그대로다 — ⛔ 코드 없이 공짜로 열리지 않는다(결제 회원만 사용).

## 앱이 부르는 것 (앱은 npm SDK 없이 REST 만)
1. **가입**: `POST {SUPABASE}/auth/v1/signup` 본문 `{email, password}` (공개 키 헤더). → 이메일 확인이 켜져 있으면 확인 메일 안내를 앱이 보여 준다. **이 설정(이메일 확인 켬/끔)을 알려 달라.** 끄는 쪽이 앱 가입 흐름이 가장 매끄럽다(코드까지 한 번에).
2. **코드 사용**: RPC `priming_redeem_code(p_code text)` — 로그인한 사용자(토큰) 호출, security definer.
   - 성공 `{ ok:true, expires_at, days, points_granted? }` — `priming-app` 기수 `enrollments` 를 만들거나(이미 회원이면 **만료일 뒤로 연장**) 만료일 = (이미 유효하면 기존 만료일, 아니면 지금) + 코드의 일수.
   - 실패 `{ ok:false, reason }` — `invalid_code`(없는 코드) · `already_used`(1회용 코드가 이미 쓰임) · `code_expired`(코드 유효기간 지남) · `rate_limited`(틀린 코드를 연달아 넣음 — 사용자당 시간당 몇 회 상한을 걸어 코드 무차별 대입을 막아 달라) · `no_login`.
   - 코드는 **1회용**(권장), 대소문자·하이픈 무시.
3. (선택) 코드에 **기본 무상 포인트 100pt**(정책 7-3 ②)를 함께 지급하게 할지 — 서버가 정하면 `points_granted` 로 돌려준다.

## 서버 쪽에서 해 줄 것
- 마이그레이션: `app_redeem_codes(code, days, points, max_uses/used_by, code_expires_at, created_at, note)` + RPC `priming_redeem_code`.
- 관리자 화면 「Priming 앱」: 코드 만들기(일수 · 포인트 · 메모 · 개수 일괄 생성) · 목록 · 사용 여부 · 취소.
- 가입 직후 **약관·개인정보 동의(`user_consents`)**: 앱이 가입 화면에서 동의 체크를 받으면 같은 값을 어떻게 남길지(사이트 규칙) 알려 달라 — 앱은 `p_consent` 같은 인자나 별도 RPC 로 보낼 수 있다.
- 구글로 이미 가입한 회원도 앱에서 코드를 넣을 수 있게(로그인 화면의 「가입 코드 입력」) — 비밀번호가 없으면 사이트 「내 기기」 안내는 그대로.

## 앱이 할 것 (Priming 세션)
- 로그인 화면에 「회원가입」·「가입 코드로 이용 시작」 추가 → 위 1·2 를 부른다. 서버가 위 약속대로 만들어지면 연결한다. 시험은 이 PC 안 가짜 서버로 먼저.

## 답으로 받고 싶은 것
- 이메일 확인 설정 · `priming_redeem_code` 응답 꼴 최종본 · 동의 저장 방식 · 마이그레이션 파일 이름(로이가 SQL Editor 에서 실행해야 켜진다).
