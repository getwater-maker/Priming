# 유튜브 업로드 — 상세 규칙

> 2026-10-09 CLAUDE.md 슬림화 2차에서 **원문 그대로** 옮겼다. 지금도 유효한 규칙이다 — 이 기능을 고치는 세션은 먼저 읽는다.
> 새 규칙은 여기에 한 줄 더하고, CLAUDE.md 에는 ⛔/🔴 금지선만 요약한다.

- 유튜브 업로드: 전용 GCP 프로젝트 `priming-upload`(youtube.upload+readonly). ⛔ 분석용 `adonairoy` 프로젝트 토큰 사용 금지. 비공개 + `containsSyntheticMedia` + ko(⚠ 언어 고정 — 다국어 시 분기 필요). 제목·설명·태그는 아도나이로이 패키징 파일. 챕터는 `core/yt-chapters.js` 하나(⏱ 창과 공유), 업로드 전 MP4 실측 길이와 대조. 🔑 **기본 연결은 앱에 들어 있다**(v0.5.91 · 로이 2026-09-30 「앱에 넣어 배포」 — `core/youtube-default-client.js` 한 곳, 업로드 전용 `priming-upload` 클라이언트 · 데스크톱 앱 비밀은 구글도 비밀로 안 본다). 사용자는 **채널 연결만**(PC·계정별 · 그 PC 에만 암호화). 자기 프로젝트 파일은 「고급」(자기 한도). ⛔ 분석용 `adonairoy` 값·`client_secret_*.json` 원본 파일은 저장소에 절대 넣지 않는다(테스트가 잡는다). 공용 연결은 **PC 하루 상한 30편**(`DEFAULT_DAILY_CAP` — 구글 한도는 프로젝트 하나를 모두가 나눠 쓴다) · 자기 프로젝트는 앱 상한 없음. 악용되면 구글 클라우드에서 비밀 교체 → 이 파일만 교체 → 전원 채널 재연결. 🛡 **중복 방지 관문 = `runYtUpload` 한 곳**(v0.5.105): `YT.checkDuplicate`(같은 파일 · 이 PC 기록의 같은 제목 · **유튜브 채널 업로드 목록의 같은 제목**) — 새 업로드 경로는 반드시 `enqueueYtUpload` 로(관문을 우회하지 말 것) · 이 대본만은 묻고 「한 번 더」만 `force` · 확인 실패는 fail-open. ⬆ 큐 전체 = `planQueueUploads` 한 곳(채널 항목 우선 · 이미 올린 파일·MP4 없음은 건너뛰고 로그). API 한도 = **하루 100편**(videos.insert 전용 버킷, 편당 1 — 옛 「1600단위·6편」 아님).
- 🧷 **업로드 마무리 = `core/yt-finish` 한 곳**(v0.9.33): 썸네일 A(`thumbnails.set`) · 재생목록(`playlistItems.insert` → **다시 읽어** 판정) · 고정댓글·A/B·종료화면·예약은 「✋ Studio」로 확인표에 적는다. 새 업로드 줄 세우기는 `finish: ytFinishJob(ctx, preset)` 를 실을 것(줄 세운 순간의 대본 — 화면 대본 금지) · 마무리는 던지지 않는다(업로드 성공을 뒤집지 않음) · 결과 줄에 ✗·❌ 금지(빠짐은 ⚠) · 재생목록 이름 자동 유사 매칭 금지. 권한 `youtube.force-ssl` 추가 — 옛 연결은 `needsReconnect`. `test/yt-finish.test.js`.
- ⏰ **예약 업로드 = `core/yt-schedule` 한 곳**(v0.9.68): 채널 `ytSchedule{on,time(KST)}` → `runYtUpload` 가 계산해 `uploadVideo({publishAt})` 로 싣는다(UTC ISO · private 과 함께 · 미래만) · 하루 한 편(채널별 마지막 배정 기록은 **성공 뒤에만**) · 올린 뒤 `yt-finish` 가 `videos.list` 로 **다시 읽어** ✅/⚠ · ⛔ 공개 즉시 업로드 금지(로이 결정 전) · ⛔ 채널 값을 `youtube-upload.js` 에서 해석하지 않는다(`test/yt-schedule.test.js`). 구글 심사 서류 = `docs/유튜브-API심사-신청서.md`.
- 🔑 **「미심사 프로젝트는 API 업로드 영상이 비공개로 잠긴다」는 틀렸다(2026-10-19 실측)** — 구글 공식 `videos.insert` 문서: 「Videos uploaded from unverified API projects are not restricted to private viewing mode」 · 이 프로젝트가 API 로 올린 영상을 Studio 에서 「일부 공개」로 바꿀 수 있었다(잠금 없음). 앱이 private 만 보내는 것은 **안전한 기본값(로이 선택)** 이지 구글의 강제가 아니다 · 「API Services 감사(Audit) 양식」의 공식 용도는 **할당량 확대**(이 앱은 하루 30편 상한이라 불필요) · ⛔ 「예약을 하려면 감사가 필요하다」고 다시 안내하지 말 것. 구글 OAuth 앱 인증(브랜딩·범위)은 별개 — 다른 사용자에게 팔 때 「확인되지 않은 앱」 경고와 100명 한도를 없애는 용도.
