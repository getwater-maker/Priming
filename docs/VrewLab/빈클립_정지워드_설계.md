# 빈 클립 · 빈 워드 · 정지 워드 삽입 설계 (2026-10-25)

> 상태: ✅ **구현 완료(2026-10-25 · 권장안 그대로)** — 결과·실측은 작업노트 「빈 클립」「정지 워드」 절. 설계와 달라진 점: ① 단어 시각 열쇠 `k` 를 새 소리 기준으로 **다시 찍어야** 한다(경로·길이를 품음) ② 칩 곁 ⏸ 단추는 Cards props 대신 창 이벤트로 연결 ③ 「앞에 삽입」은 v1 제외(설계대로).
> 근거: `core/pipeline.js` `pausePlanOf`·`padAudioTo`(막간 쉼) · `core/word-align.js` `cutWords`·`s.wt`(단어 시각) · `main.js` `delete-words`(새 WAV 만드는 선례) · `vrew-render.js` `pauseCaptionWins`.

## 0. 한 줄 결론

세 기능은 **새 자료형을 만들지 않고**, 이미 있는 두 길 위에 얹는다.
- **빈 클립 = 문장 뒤 무음**(`s.padAfter` 초) → 이미 있는 **막간 쉼 계획 `pausePlanOf` 한 곳**에 합친다. 빌더·SRT·챕터·화면 카드·정보 카드·DTO `pz`·지문이 **그 한 곳을 이미 읽는다** → 새로 고칠 소비처가 거의 없다.
- **정지 워드 = 문장 음성 안의 단어 사이 무음**(소리를 단어 경계에서 갈라 무음을 끼운 **새 WAV**) → 단어 지우기(`delete-words`)와 같은 길. 단어 시각 `s.wt` 를 같이 밀어 정렬이 깨지지 않는다.
- **빈 워드 = 정지 워드의 짧은 꼴**(0.3초 기본, 글자 없음) — Vrew 의 「빈 워드」는 단어 자리를 하나 비워 타이밍을 벌리는 도구인데, Priming 은 글(.md)이 정본이라 글에 빈 칸을 넣을 수 없다 → **같은 동작을 소리 쪽으로만** 한다(§3-3).

## 1. 지금 코드에서 확인한 사실

| 사실 | 의미 |
|---|---|

| 단어 시각 `s.wt = {k, b[]}`(어절 경계 초) — 한국어 + 채널 「단어 자리 맞추기」일 때만 있다 | 정지 워드는 이 경계가 있어야 **정확히** 갈 수 있다. 없으면 문장 맨 앞·끝만(§3-2) |
| `delete-words` 는 새 WAV(`<번호>_d<지문>.wav`)를 만들고 `_editSentences({_wordCut})` 로 글·음성을 한 번에 바꾼다 · 이때 `s.quiet`·`clipSpeed`·`quietOver`·`wt` 를 비운다(main.js:9305) | 정지 워드도 같은 틀(새 WAV · 원본 불변 · Ctrl+Z 한 번) |
| 쉼 줄이기(`quietPass`)는 채널 `quietMaxSec` 보다 긴 무음을 **줄인다** | 사용자가 일부러 넣은 무음이 도로 줄어든다 → **지켜야 한다**(§4-2) |

## 2. 용어 정리 (Vrew ↔ Priming)

| Vrew | 하는 일 | Priming 대응 | 저장 |
|---|---|---|---|
| **빈 클립 삽입** | 고른 클립 앞/뒤에 글 없는 빈 클립(무음 구간) | 그 클립 **뒤에 N초 무음** — 화면은 그대로 이어지고 자막은 없다 | `s.padAfter`(초) |
| **정지 워드 삽입** | 클립 안 커서 자리에 정지(무음) 구간 | 단어 사이에 N초 무음 | 새 WAV + `s.wt` 이동 + `s.pauseIn[]`(기록용) |
| **빈 워드 삽입** | 단어 자리 하나를 비워 둠 | 정지 워드와 같은 동작, 짧게(기본 0.3초) | 〃 |

> ⚠ Vrew 화면에서 세 항목의 **정확한 동작**은 캡처(`vrew-화면/`)에 이름만 있고 동작은 없다. 위 대응은 이름과 Vrew 의 클립·워드 구조(클립 = 자막 한 줄 = 단어 모음)에서 추정한 것이다 → **「로이 확인」 항목**(§8).

## 3. 기능별 설계

### 3-1. 빈 클립 삽입 = `s.padAfter`

- **조작**: ② 클립 우클릭 ▸ 삽입 ▸ 「빈 클립 삽입」 → 작은 패널(길이 0.2~10초, 기본 1.0초 · 「뒤에」만). 같은 클립에 또 넣으면 **더한다**(1.0 + 1.0 = 2.0 — 패널에 지금 값을 보여 준다) · 0 으로 하면 지운다.
- **첫 클립 「앞에」**: 글 없는 클립이 맨 앞에 오는 경우 = 그 문장의 **앞 여백**. 쉼 계획은 「문장 뒤」만 안다 → **첫 문장의 `padBefore`** 를 따로 두지 않고 v1 에서는 **「뒤에」만 지원**(앞에 넣고 싶으면 앞 클립의 뒤에). 안내 문구로 알린다.
- **합치는 규칙**: `pausePlanOf` 가 `map[sentenceId] = max/sum(카드 쉼, s.padAfter)` — 카드 쉼(막간)과 같은 문장이면 **합**(카드 쉼 동안 카드가 뜨고, 그 뒤 빈 클립이 이어진다고 보는 것이 자연스럽다) → 합으로 정한다.
- **조건**: 음성이 있는 문장만(카드 쉼과 같다). 음성이 없으면 거부 + 안내.
- **화면**: ② 클립 아래에 얇은 줄 「⏸ 빈 클립 1.0초」(이미 있는 카드 쉼 표시 `pz` 와 같은 자리·같은 스타일 — 새 줄 종류를 만들지 않고 `pz` 표시를 재사용).
- **MP4**: 쉼 동안 자막 숨김 — 옆 파일 `pauseWins:[[t0,t1],…]` 를 렌더러가 `pauseCaptionWins` 에 합친다(전환 옆 파일과 같은 파일·같은 읽는 곳).
- **되돌리기·이어받기**: 문장 필드 → 마커·볼륨과 **같은 길**(DTO `pa` · 작업본 저장·이어받기 2곳 · 글 고침 유지 · IPC `clip-pad`).

### 3-2. 정지 워드 삽입 = 새 WAV

- **조작**: 클립 편집 중 **커서 자리**에서(Vrew 와 같다) 우클릭 ▸ 「정지 워드 삽입」 / 편집 줄 막대 단추 → 길이 패널(0.1~5초, 기본 0.5초).
- **자리 판정**: 커서 글자 위치 → `word-align.tokenRange` 로 **어절 경계 j**(커서가 어절 가운데면 **가까운 쪽 경계**). 경계 시각 `b[j]` 가 있어야 한다.
  - `s.wt` 있음 → 정확히.
  - 없음 → **문장 맨 앞(j=0)·맨 끝(j=n)만** 허용(앞·끝 무음은 경계가 필요 없다) · 가운데는 거부 + 「채널 편집 → 음성 → 단어 자리 맞추기를 켜세요」(`delete-words` 와 같은 안내).
- **소리 만들기**: `word-align-pass` 에 `insertSilenceAudio({src, bounds, j, sec, outPath, ffmpegPath})`(= `deleteWordsAudio` 의 짝) — 경계에서 PCM 을 둘로 갈라 **무음(0) `sec`초**를 끼운다. 이은 자리 양쪽 8ms 페이드(딸깍 방지 · `cutWords` 와 같다). 새 파일 `<번호>_p<지문>.wav`(`claimPath` · 원본 불변 · Ctrl+Z 가 옛 소리로).
- **단어 시각 갱신**: `b'[i] = b[i] (i < j)`, `b'[i] = b[i] + sec (i ≥ j)` — 정렬이 **그대로 유효**(쉼 시각만큼 뒤가 밀린다) → `s.wt` 를 **비우지 않고** 새 값으로 갈아 끼운다(자막 줄 시각·단어 지우기·단어부터 재생이 이어서 동작).
- **자막**: 글은 안 바뀐다. 줄 경계 시각은 `wt` 에서 오므로 쉼이 낀 줄은 **쉼을 포함해 길어진다**(Vrew 도 단어 사이 정지는 클립 안에 있다) — MP4 쉼 동안 자막 가림은 §3-1 의 `pauseWins` 에 **정지 워드 구간도 넣을지**는 §8-3(기본: 넣지 않음 — 말하다 멈추는 것이라 자막은 남는 편이 자연스럽다).
- **저장**: 새 WAV 가 곧 소리라 문장 필드는 `ttsAudioPath`·`ttsDurationSec`·`wt` 뿐. 거기에 **`s.keepSil = true`**(쉼 줄이기 면제 표시 · §4-2)와 기록용 `s.pauseIn=[{j,sec}]`(해제·표시용).
- **되돌리기**: IPC 한 번 = `undoPush` 한 번(`delete-words` 와 같다).

### 3-3. 빈 워드 삽입

- 정지 워드와 **같은 IPC·같은 소리 처리**, 기본 길이만 0.3초 · 메뉴 이름만 다르다. 「글에 빈 칸」은 만들지 않는다 — 글(.md)이 정본이고 TTS 입력이라(`processForTTS`) 빈 어절이 낭독·자막·지문을 어지럽힌다. Vrew 에서 빈 워드가 하던 일(단어 타이밍을 벌려 자막·효과를 맞춤)은 정지 워드로 충분하다.
- 화면에는 「빈 워드」를 따로 보이지 않고 정지 워드 기록(`pauseIn`)으로 한꺼번에 보인다.

## 4. 공통 규칙 · 위험

### 4-1. 한 곳 규칙

- **빈 클립 길이 합산은 `pausePlanOf` 한 곳** — ⛔ 빌더·SRT·화면에서 `padAfter` 를 따로 읽지 않는다. 새 소비처가 생기면 `pausePlanOf` 를 거친다(CLAUDE.md 의 막간 쉼 규칙 그대로).
- **무음 끼우기는 `word-align-pass` 한 곳**.

### 4-2. 위험과 대응

| 위험 | 대응 |
|---|---|
| **쉼 줄이기가 일부러 넣은 무음을 도로 줄인다** | `s.keepSil` 문장은 `quietPass` 가 건너뛴다(배속은 그대로 적용 — 쉼도 함께 빨라지는 것은 의도). 시험: `quietMaxSec` 를 켠 채널에서 정지 워드 문장의 길이가 줄지 않는다 |
| 소리를 바꾸는 새 경로 = `s.quiet`·`clipSpeed`·`quietOver`·`wt` 를 **비우는 선례**(delete-words)와 달리 정지 워드는 `wt` 를 **유지**한다 | 이미 배속·쉼 줄이기가 구워진 소리 위에 끼우므로 `quiet`·`clipSpeed`·`quietOver` 기록은 비운다(두 번 걸림 방지) · `wt` 는 새 경계로 갈아 끼움 — **어느 쪽인지 시험이 단언** |
| `wt` 가 옛 소리 기준이면(배속 뒤 등) 경계가 어긋남 | `s.wt.k`(텍스트 열쇠) + 길이 검증 — 맞지 않으면 `delete-words` 처럼 거부 |
| 글 고침 뒤 옛 `pauseIn`·`keepSil` 이 남음 | 글이 바뀌면 음성도 새로 만들어지므로(화자·글 변경 = 음성 물려받지 않음) `pauseIn`·`keepSil`·`padAfter` 는 **글이 같을 때만** 따라온다(`keep.*` 규칙) |
| 큰 대본(수천 문장)에서 `pausePlanOf` 비용 | 문장 필드 한 번 훑기 — 카드 계획과 같은 규모(이미 DTO 마다 부름) |
| `withPauses`(정보 카드·챕터 시각)에 `padAfter` 가 빠지면 시각이 어긋남 | `pausePlanOf` 의 map 이 이미 합쳐져 나오므로 자동 · 시험이 챕터 시각으로 확인 |
| 화이트보드 MP4 | 적용 안 함(다른 효과와 같다) · 안내 |

## 5. 데이터 모델 변경 요약

| 필드 | 위치 | 기본 | 읽는 곳 |
|---|---|---|---|
| `s.padAfter`(초 · 0.2~10) | 문장 | 없음 | `pausePlanOf`(한 곳) → 빌더·SRT·지문·DTO `pz`·챕터·카드 |
| `s.keepSil`(참) | 문장 | 없음 | `quietPass` 만 |
| `s.pauseIn[{j,sec}]` | 문장 | 없음 | 화면 표시 · 해제 |
| DTO `pa`·`pi` | 문장 DTO | 없음 | 클립 배지·② 줄 |
| `.vrew.fx.json` `pauseWins` | 옆 파일 | 없음 | MP4 렌더러(자막 가림) |

> 마커·볼륨과 같이 **문장 필드는 작업본 저장·이어받기 2곳 · 글 고침 유지 · IPC · DTO** 를 한 벌로 넘긴다.
> 지문: `s.padAfter` 는 `pausePlanOf` 를 거쳐 `inp.pauses` 에 이미 들어간다. `keepSil`·`pauseIn` 은 소리 파일 자체가 바뀌므로 경로 변화로 지문이 바뀐다 — 별도 처리 없음(시험이 `fpOf` 로 확인).

## 6. 시험 설계

1. **순수**: `pausePlanOf` 가 카드 없이도 `padAfter` 를 담는다 · 카드 쉼과 합 · 음성 없는 문장 제외 · 한도 자름. `insertSilenceAudio` 길이 = 원본 + sec(±1프레임) · 경계 앞뒤 소리 보존(파형 비교) · 경계 밖 거부.
2. **🔑 실제 왕복**(빌더 → 렌더러 → ffmpeg): 빈 클립 1초 → `.vrew` 의 그 문장 음성이 +1초 · MP4 길이 +1초 · SRT 뒤 자막이 1초 밀림 · MP4 쉼 동안 자막이 없다(`pauseWins`) · 챕터 시각이 밀림.
3. **🔑 정지 워드**: 소리 한가운데 무음 구간이 **실측**(volumedetect/silencedetect)으로 sec 만큼 · `wt` 가 밀려 자막 줄 시각이 그만큼 늦어짐 · `quietMaxSec` 를 켠 빌드에서도 줄지 않음(`keepSil`) · 원본 WAV 불변.
4. **화면 E2E**: 우클릭 메뉴 → 패널 → DTO 필드 · 배지 · Ctrl+Z · 새로고침 유지 · 같은 클립에 또 넣으면 합산.
5. **회귀**: `test:pause`·`test:buildfp`·`test:quiet`·`test:wdel`·`test:makeall`·`test:mp4`·`test:cliptb`·`test:workspace`.

## 7. 단계 제안 (작은 것부터 · 각 단계가 독립으로 낼 수 있다)

## 8. 로이가 정해 주실 것 (권장안 포함)

1. **빈 클립은 「문장 뒤 무음」으로 정해도 되는가**(글 없는 별도 행을 ② 에 만들지 않고 쉼 표시 줄로 보임). *권장: 예 — 새 자료형이 없고 빌더·MP4·SRT·챕터가 이미 한 곳으로 따라온다.*
2. **「앞에 삽입」은 v1 에서 제외**(앞 클립 뒤에 넣는 것으로 대체)해도 되는가. *권장: 예.*
3. **정지 워드 구간에 MP4 자막을 숨길까**. *권장: 숨기지 않음(말하다 멈춤 = 자막 유지) / 빈 클립만 숨김.*
4. **빈 워드는 정지 워드의 짧은 꼴(0.3초)로 합쳐도 되는가**(글에 빈 칸은 만들지 않음). *권장: 예.*
