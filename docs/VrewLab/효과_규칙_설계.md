# 효과 5종 규칙 설계 — 볼륨 · 클립 배경색 · 필터 · 화면 전환 · 확대 및 회전 (2026-10-25 · 로이 확인 대기)

목적: Vrew 효과 메뉴의 5개를 만들 때 **`.vrew` 빌더 · 🎬 MP4 렌더러 · ① 미리보기 · 메뉴 화면**이 같은 규칙을 쓰게 한다 — 미리보기와 출력이 어긋나는 것이 이 저장소의 단골 사고라서(켄번스 3벌·자막 위치 2벌·로고 규칙 흩어짐 → Lab 에서 `ken-burns`·`caption-geom`·`overlay-layers` 한 곳으로 모은 것과 같은 방식).

## 0. 한 줄 결론

- **새 순수 모듈 `core/clip-effects.js` 한 곳**이 표·정규화·ffmpeg 식·CSS 식·설명 글을 모두 만든다(렌더러 번들에도 들어가므로 CJS 런타임 참조 금지). 빌더·렌더러·미리보기·메뉴는 이것만 부른다.
- 효과마다 **「어떻게 출력에 실리나」** 가 다르다 — 세 가지 운반 방식 중 하나로 정한다.

| 효과 | 저장 | 운반 방식 | `.vrew` | 🎬 MP4 | ① 미리보기 | 일치 보증 |
|---|---|---|---|---|---|---|
| **확대 및 회전** | 그룹 `look.box`(이미 있음) + 새 `look.rot`(°) | **Vrew 필드** — 트랙 `xPos·yPos·width·height·rotation` | ✅ 그대로 | `.vrew` 를 읽어 회전(`rotate`+투명) | CSS `transform: rotate()` + 박스 | 화소 시험(박스 모서리 좌표) |
| **필터** | 그룹 `look.filter`(id) | **굽기** — 필터를 입힌 그림·영상 사본을 만들어 `.vrew` 가 그 사본을 가리킨다 | ✅ 사본 | 렌더러 변경 없음 | CSS `filter:` 같은 표 | 같은 장면 평균색 비교 |
| **클립 배경색** | 그룹 `look.bg`(#RRGGBB) | **굽기** — 맞추기(contain) 띠·투명 PNG 바닥을 칠한 캔버스 크기 사본 | ✅ 사본 | 렌더러 변경 없음 | CSS `background-color` | 띠 화소색 |
| **볼륨 조절** | 문장 `s.vol`(0~2 · 기본 1) | **굽기** — 문장 음성을 MP3 로 바꿀 때(`preConvertWavsToMp3`) `volume=` 을 얹는다 | ✅ 문장 MP3 | 렌더러 변경 없음(.vrew 의 음성을 쓴다) | 재생 음량(WebAudio 이득) | `volumedetect` 평균 음량 비 |
| **화면 전환** | 그룹 `look.trans{type,sec}` = 「앞 그룹에서 이 그룹으로」 | **렌더러 전용 옵션** — 디졸브(`planDissolves`)와 같은 자리 | ⛔ 못 담는다(컷) | `xfade` | CSS 로 같은 종류 | 경계 프레임 화소 |

> 「굽기」를 고른 이유: Vrew 4.8.1 의 **필터·전환·배경색 필드 모양을 우리는 모른다**(분석 §9 「아직 모르는 것」). 모르는 필드를 추측해 쓰면 Vrew 가 파일을 거부할 수 있다. 사본을 만들어 가리키면 **Vrew 가 아는 형식(그림·영상·음성 파일)만** 쓰므로 안전하고, 렌더러를 고치지 않아도 MP4 가 같아진다. 회전·이동·크기는 Vrew 가 아는 트랙 필드(`rotation`·`xPos`…)가 이미 빌더에 있다.

## 1. 지금 코드에서 확인한 사실

- 그림 「모양」은 **그룹마다 `g.look`**(`core/visual-look`: `fill·flipH·flipV·motion·box·fx·kbSeg`) — `normLook`/`isDefault`/`describe` 가 한 곳, `set-group-look` IPC 로 바꾼다. 빌더는 이것을 트랙 박스·`editInfo.flip`·`kenburnsAnimationInfo` 로 적고(`vrew-builder` ~930~1010행), 렌더러는 **그 `.vrew` 를 읽어** `boxImage`(박스·반전)·`kenBurnsFilter` 로 굽는다 — 앱 모델에서 렌더 규칙을 다시 계산하지 않는다(CLAUDE.md §7).
- 트랙의 `rotation` 은 **항상 0** 으로 쓰고 있고(빌더 `rotation: 0`), 렌더러는 회전을 그리지 않는다 → 회전은 두 곳 모두 새로 필요.
- 문장 음성은 **문장마다 MP3 한 개**(`preConvertWavsToMp3` 가 WAV → 24k 모노 MP3). 그룹 영상 소리는 `volume:0`(내레이션과 겹침 · 확정 결정). 삽입 오디오·BGM 은 이미 `volume` 이 있다 — 여기서 말하는 볼륨은 **내레이션(문장 음성)** 이다.
- 디졸브(`planDissolves`)는 **렌더러 옵션**(`opts.dissolveSec`)으로 들어가고 `.vrew` 에는 안 실린다(「MP4 만」) — 화면 전환은 이 선례를 따른다. (채널 설정의 디졸브는 v0.9.18 에 뺐다 — 다시 읽게 하면 칸 없이 숨은 채로 적용된다는 이유. 그룹 `look.trans` 는 **칸이 있는** 값이라 이 금지에 걸리지 않는다.)
- ② 클립 화면의 효과 메뉴는 **그룹 단위**로 일한다(「맞춤·채움」이 `clipGroup()` → `setGroupLook`). 5개 효과도 같은 단위 — 고른 클립이 든 그룹(여럿이면 각각).

## 2. 공통 원칙 (모든 효과)

1. **기본값 = 예전과 같다**. 효과가 꺼져 있으면 필드를 두지 않고(`normLook` 이 안 만든다) `.vrew`·MP4 가 예전과 한 글자도 다르지 않다(`test:buildfp`·`test:mp4` 가 그대로 통과해야 한다).
2. **표는 한 곳**: `core/clip-effects.js` = `FILTERS`·`TRANSITIONS`·`ROT_RANGE`·`VOL_RANGE` + `normEffects` + `ffmpegFilter(id)` + `cssFilter(id)` + `bakeKey(look)`(사본 이름 지문) + `describe`. ⛔ 화면·렌더러·빌더에 색 계산·각도·음량 규칙을 따로 두지 않는다(켄번스 때의 3벌 사고).
3. **굽기 규칙**(필터·배경색·볼륨): 원본은 그대로 · 사본 이름 `<번호>_fx<지문>.png|mp4|mp3`(⛔ 고정 이름 덮어쓰기 금지 — Ctrl+Z 가 옛 모양으로 돌아가야 한다 · `P.claimPath` 를 거친다) · 사본 정보(원본 경로·지문)를 기억해 효과를 끄면 원본으로 되돌린다(`s.quiet` 와 같은 모양 — 그림은 `g.fxCopy`) · 그림을 새로 만들면(🔄·AI) 사본을 버리고 새 그림에 다시 굽는다.
4. **이어받기**: 문장 필드(`vol`)는 `clipSpeed`·`quietOver`·`marker` 와 **같은 자리**(작업본 저장·이어받기 2곳·글 고침·DTO)로 · 그룹 `look` 은 이미 작업본·되돌리기·합치기에서 따라간다(`g.look`) — 새 키만 `normLook` 에 더하면 된다.
5. **빌드 지문**: `look` 은 이미 지문에 들어 있다(`vrewInputsOf` `look: g.look`) · `s.vol` 은 새로 넣는다(빠뜨리면 음량만 바꿨을 때 .vrew 를 안 다시 만든다 — `test:buildfp` 가 잡게).
6. **일치 시험은 실측으로**: 같은 입력을 ① ffmpeg 굽기 결과 ② 미리보기 식(Electron 캔버스 `ctx.filter`/`transform`)으로 만들어 **화소 평균·모서리 좌표를 비교**(허용 오차 명시) — 「식이 같다」가 아니라 「결과가 같다」를 본다.
7. **화이트보드 MP4 는 효과를 쓰지 않는다**(`look` 과 같은 이유 — 그림 위 주석 좌표가 원본 기준).

## 3. 효과별 설계

### 3-1. 확대 및 회전
- UI: 효과 ▸ 확대 및 회전 → 작은 패널(확대 100~300% · 회전 −180~180° · 초기화). 확대는 **화면 중앙 기준 `look.box` 를 키우는 것**(이미 있는 ① 칸 끌기와 같은 필드 — 둘이 서로를 덮어쓴다는 점을 패널에 한 줄 안내).
- 저장: `look.rot`(정수 °) 새 키. `isDefault` 에 포함.
- `.vrew`: 빌더가 `track.rotation = look.rot`(지금은 0 고정). Vrew 가 이 필드를 아는 것은 `.vrew` 형식 확인(`xPos·yPos·width·height·rotation`)에서 이미 확인됨.
- 🎬 MP4: `boxImage` 가 박스 크기로 만든 PNG 를 **투명 바탕 위에서 `rotate=a:c=none:ow=rotw:oh=roth`** 로 돌려 overlay(회전 중심 = 박스 중심). 회전이 있으면 켄번스는 건너뛴다(**구현 전 확인**: 박스가 있는 그림에서 켄번스를 지금 어떻게 하는지 — 박스 경로는 켄번스 없이 고정 크롭으로 보인다).
- 미리보기: ① 칸 그림에 `transform: rotate(…)` + 박스 위치(`overlay-layers.logoBox` 처럼 한 곳의 좌표 함수 `boxPx(look, canvas)` — `caption-geom.boxPx` 와 같은 습관).
- ⚠ 영상 그룹에도 적용되는가 — 박스·반전이 이미 영상에도 적용되므로 같게(렌더러 영상 경로 확인).

### 3-2. 필터
- 표 `FILTERS`: **CSS 와 ffmpeg 가 같은 뜻을 갖는 연산만** — 밝기(곱)·대비·채도·색조(°)·흑백·세피아·흐림(px). 예: 흑백 · 세피아 · 따뜻하게(세피아 40% + 채도 1.1) · 차갑게(색조 −15°) · 선명하게(대비 1.15 · 채도 1.2) · 어둡게 · 밝게 · 빈티지. 각 항목은 `{id, label, css:'sepia(.4) saturate(1.1)', ff:'colorchannelmixer=… ,eq=…'}` 를 **한 표에서 함께** 정의하고, 표 검사 시험이 「css 와 ff 의 결과가 같은지」를 단색 장면으로 잰다.
  - 주의: CSS `brightness()` 는 곱, ffmpeg `eq=brightness` 는 더하기라 뜻이 다르다 → ffmpeg 쪽은 `eq` 대신 `lutrgb`/`colorchannelmixer` 로 **곱** 을 쓴다.
- 굽기: 그림 = `ffmpeg -i NN.png -vf <ff> NN_fx<지문>.png` · 영상 = 같은 필터로 재인코딩(오래 걸린다 → 백그라운드·진행 표시·`localGpu` 아닌 `upscale` 레인처럼 CPU 전용 레인).
- `.vrew` 는 사본을 가리킨다 → Vrew 에서 열면 필터가 **이미 입혀진 그림**(Vrew 의 필터 메뉴로는 못 끈다 — 알려 줄 것).

### 3-3. 클립 배경색
- 효과 범위: **맞추기(contain)로 생기는 위아래·좌우 띠**와 **투명 PNG 의 투명한 부분**. 꽉 채우기(cover)면 보이지 않는다(패널에 안내).
- 굽기: 캔버스 크기 사본(`pad`/`overlay` 로 배경색 위에 그림을 놓음) → 빌더는 그 사본을 `fill:cover` 로 놓는다(= 사본이 이미 캔버스 크기라 같은 결과). 켄번스는 **사본 위에서** 돈다(띠도 함께 확대되는 것 — 예전 contain 의 검은 띠가 확대되던 것과 같은 동작이라 일관).
- 미리보기: 프레임 `background-color`. 기본(없음) = 검정 그대로.

### 3-4. 볼륨 조절
- 단위: **문장**(`s.vol` 0~2, 기본 1 = 필드 없음). UI: 슬라이더 0~200% + 「1× 로」.
- 굽기: `preConvertWavsToMp3` 의 ffmpeg 에 `-af volume=<vol>`(클리핑 방지로 1 초과면 `alimiter` ⛔ — **TTS 규칙 「리미터·압축 금지」** 와 부딪힌다 → **1 초과는 피크 여유(정규화된 음성의 피크 − 안전폭)만큼만 허용**하고 넘으면 자동으로 깎는다고 알림). 문장 사이 쉼(`apad`)·배속·쉼 줄이기 사본 체인과의 **순서**: 쉼 줄이기 → 배속 → **볼륨(마지막)** (소리 길이가 안 변하므로 시각 규칙·`pausePlanOf`·단어 정렬에 영향 없음).
- 미리보기: ② 재생이 `audio.volume = min(1, vol)` + 1 초과는 WebAudio `GainNode`. (미리보기 재생 경로 두 곳 — 문장 재생·그룹 재생 — 확인 필요.)
- 그룹 영상 소리(`volume:0`)·BGM·삽입 오디오는 이 효과의 대상이 아니다(BGM·삽입은 이미 자기 음량 칸이 있다).

### 3-5. 화면 전환
- 의미: **그룹 경계**에서 앞 그림 → 이 그림으로 넘어가는 방식. `look.trans = { type, sec }`(type ∈ 없음·디졸브·검정 거쳐·왼쪽으로 닦기·밀기 · sec 0.3~3). 없음(컷)이면 필드 없음.
- 🎬 MP4: 지금 `planDissolves(chunks, sec)` 가 하는 일(경계 앞뒤를 잘라 섞기)을 **경계마다 type·sec 를 받는** 형태로 일반화 — `xfade=transition=<dissolve|fadeblack|wipeleft|slideleft>`. 오디오는 이어지므로 건드리지 않는다. 한 경계의 앞·뒤 그림이 모두 한 덩어리(`single`)일 때만(지금 디졸브 조건 그대로) · 전환 길이가 앞 그룹 길이보다 길면 줄인다.
- `.vrew`: ⛔ 못 담는다(컷으로 나온다) — 디졸브 선례대로 **「🎬 MP4 만」** 이라고 메뉴·툴팁에 적는다. (Vrew 의 전환 필드를 알게 되면 이 칸만 바꾸면 된다.)
- 미리보기: ① 칸 재생이 그룹을 넘어갈 때 CSS(투명도 · translate · 마스크)로 같은 4종 — 정지 화면 비교가 어려우므로 **경계 프레임 한 장**(전환 중간 시점)을 화소로 비교하는 시험.
- 작업 순서에서 가장 마지막(렌더러 구조 변경이 가장 크다).

## 5. 시험 설계

- `test:fxtable`(단위): `FILTERS` 의 css·ff 가 **단색 8장**에서 같은 색을 내는지(허용 ±6/255) · `normLook` 기본이면 필드 없음 · 지문 안정(같은 입력 = 같은 `bakeKey`) · 판정력(필터를 바꾸면 지문이 다르다).
- `test:fxbake`(E2E, 임시 채널): 필터·배경색 굽기 → 사본 이름 `_fx` · 원본 불변 · 끄면 원본으로 · Ctrl+Z · `.vrew` 가 사본을 가리킴 · 🎬 MP4 한 프레임 평균색 = 미리보기 캔버스 평균색.
- `test:fxrot`: 회전 90° → `.vrew` 트랙 `rotation:90` · MP4 프레임에서 박스 모서리 좌표가 회전 위치.
- `test:fxvol`: 볼륨 0.5 → 문장 MP3 의 `volumedetect` 평균이 −6dB 쯤 · 1 초과 클리핑 없음 · 지문이 바뀌어 `.vrew` 를 다시 만든다.
- `test:fxtrans`(마지막): 전환 중간 프레임이 앞·뒤 그림의 섞임.
- 기존: `test:buildfp`·`test:mp4`·`test:workspace`·`test:cliptb` 회귀, 효과 끔 = 예전 `.vrew` 와 해시 동일.

## 6. 위험 · 열린 질문

1. **Vrew 에서 열기**: 굽기 사본(.vrew 가 사본을 가리킴)은 Vrew 가 아는 형식이라 안전하다고 보지만 — 로이 PC 의 Vrew 4.8.1 로 **한 번 열어 확인**이 필요(필터 사본 · 배경 사본 · 회전 트랙 · 음량이 구워진 MP3). 문제가 생기면 그 효과만 접는다.
2. **영상 필터·배경색 굽기 비용**: 그룹 영상 수십 개를 재인코딩하면 오래 걸린다 → 첫 판은 **그림(PNG)만** 굽고 영상 그룹은 「영상엔 적용 안 됨」 안내(필터·배경색은 그림 효과로 시작).
3. **볼륨 1 초과**: TTS 「리미터·압축 금지」 와의 충돌 → 위 3-4 의 「피크 여유만큼만」 규칙. 로이 확인.
4. **회전 + 켄번스**: 둘을 같이 하면 켄번스를 끈다(안내) vs 회전된 그림에 켄번스 — 렌더러 구조상 앞의 것이 쉽다.
5. **효과 단위가 그룹**이라 한 그룹에 클립이 여럿이면 클립 하나에만 줄 수 없다 — Vrew 는 클립 단위이므로 차이(씬 나누기로 해결 가능 — 방금 만든 「새 씬 만들기」).
6. 메뉴 이름·순서는 Vrew 효과 탭(필터 · 확대 및 회전 · 화면 전환 · 볼륨 조절 · 배속 효과 · 클립 배경색)을 그대로 쓴다. **잡음 제거**(AI)는 이 설계 밖.

## 7. 단계 제안 (작은 것부터 · 각 단계가 독립으로 출시 가능)

| 순서 | 단계 | 규모 | 이유 |
|---|---|---|---|
| ① | `core/clip-effects.js` 뼈대 + `look.rot`/확대 패널(회전 두 곳 + 박스) | 중 | 필드·좌표는 이미 있다. 렌더러 회전만 새로 |
| ② | **클립 배경색**(그림) | 소 | 굽기 규칙의 첫 사용 — 사본 이름·원복·지문을 여기서 굳힌다 |
| ③ | **필터**(그림) + 단색 일치 시험 | 중 | ②의 굽기 길 재사용 · css/ff 표 일치가 핵심 |
| ④ | **볼륨 조절**(문장) | 소~중 | 음성 사본 체인 순서 · 리미터 규칙 |
| ⑤ | 영상 그룹에 필터·배경색 | 중 | 재인코딩 비용 — 선택 |
| ⑥ | **화면 전환** | 대 | 렌더러 `planDissolves` 일반화 · `.vrew` 에 못 담는다 |

## 8. 로이가 정해 주실 것

1. 굽기(사본) 방식으로 가도 되는가 — Vrew 에서 열면 **필터가 이미 입혀진 그림**이 보이고 Vrew 쪽에서 필터를 끌 수 없다.
2. 첫 판은 **그림만**(영상 그룹은 안내) 으로 시작해도 되는가.
3. 볼륨은 **피크 여유 안에서만** 키우기(그 이상은 자동으로 깎고 알림) 로 정해도 되는가.
4. 화면 전환은 **「MP4 만」**(`.vrew` 는 컷)으로 정해도 되는가.
5. 순서 ①~⑥ 그대로 진행해도 되는가(또는 먼저 보고 싶은 효과).
