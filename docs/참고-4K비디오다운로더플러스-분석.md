## 0. 방법과 한계 (사실 / 추정 구분)

- REA(`open_binary`)로 `4kvideodownloaderplus.exe`(179MB · PE x86-64 · SHA-256 `50e3ea93…cebbc`)를 열었으나, **Ghidra 헤드리스 분석이 시작 제한(330초)을 넘겨 `search_strings` 가 시간초과**였다. 그래서 디컴파일은 못 했다.
- 대신 **같은 exe 의 정적 문자열(ASCII·UTF-16)을 추출해 분석**했다(프로그램 실행 없음). 근거는 전부 **문자열·C++ 타입 이름(RTTI)·소스 경로·로그 메시지**다.
- 따라서 아래는 **관찰 = 문자열에 있는 것** / **추정 = 내 해석(틀릴 수 있음)** 으로 표시한다. 함수 내부 로직(재시도 간격 값 등)은 **확인 못 함(미상)**.
- 추출 원본(작업용 임시): 스크래치패드 `strings.txt`(22만 줄) — 필요하면 다시 만든다.

## 1. 한 줄 결론

**yt-dlp 를 쓰지 않는다. 자체 C++(Qt6 + Boost + FFmpeg 라이브러리) 엔진이 사이트별 추출기를 직접 구현**한다 (YouTube 는 InnerTube API 를 직접 호출). 그래서 Priming 이 가져올 것은 코드가 아니라 **운영 설계(재시도·큐·상태·UX)** 다.

## 3. YouTube 추출 방식 (관찰) — 429·403 대응의 핵심

- **InnerTube 클라이언트를 여러 개 두고 돌려 쓴다.** 타입 이름: `Web` · `WebSafari` · `WebEmbedded` · `WebCreator` · `WebMusic` · `MobileWeb` · `Android` · `AndroidVr` · `iOS` · `Visionos` · `Tv` · `TvDowngraded` · `TvSamsung` · `TvSimply` (14종). 요청 주소 꼴 `…/youtubei/v1/<엔드포인트>?prettyPrint=false`.
- 클라이언트마다 포맷을 뽑아 보고, 실패 로그가 클라이언트별로 남는다: `can't extract formats from innertube client '%1%': status '%2%'`, `video is %1%, can't extract formats from innertube client '%2%'`.
- **PO token(YouTube 의 봇 방지 증표) 자체 생성**: `window.__POT_CONFIG = {vmLoadTimeoutMs, vmInitTimeoutMs, botguardSnapshotAttempts, botguardRetryDelayMs, fetchAttempts, fetchRetryDelayMs, fetchTimeoutMs, botguardSnapshotCapMs}` 를 **숨은 웹엔진 페이지(QtWebEngine) 안에서 실행**해 BotGuard 로 토큰을 만든다. 로그: `generateWithRetries: PO token attempt %1%/%2% failed`.
- 🔑 **토큰이 없으면 그 클라이언트는 건너뜀**: `skipping innertube client '%1%' - PO token is unavailable, its medias would produce 403:Forbidden` — **받아 봤자 403 이 날 것을 미리 알고 시도하지 않는다.** 자막도 같다: `Subtitles require PO token, track skipped`.
- 서명 해독: `PlayerNsigDecryptor`(n 파라미터 변환), `PLAYER_JS_URL`, `signatureTimestamp` 정규식, `Can't decrypt signature`. 플레이어 JS 를 받아 해독 루틴을 뽑는 방식(= yt-dlp 와 같은 원리).
- 로그인: `ServiceLogin` 주소를 웹엔진으로 열고 쿠키를 `addWebengineCookies` 로 앱 쿠키 저장소에 옮긴다(`CookiesStorage`, `HttpSessionEmulatorCookiesExt`). 효과 문구: 「연령 제한 영상·비공개 재생목록(나중에 볼 동영상·좋아요) 받기」.
- 방송 전체가 **로그인=선택 기능**이다(「Secure Google sign-in」 문구 · 비밀번호는 구글 창에서만).

## 4. 429/제한/재시도 (관찰 + 미상)

- `Too Many Requests`, `Retry-After`, `exceeded_rate_limit`, `throttle-speed`, `throttle-duration-sec`, `Initialized: throttleSpeedBitPerSec %1%, minThrottleDuration %2%` 가 있다 → **서버가 보낸 대기 시간 헤더를 읽고, 속도 저하(스로틀)를 감지하는 설정값이 있다.** (추정: 일정 시간 느리면 연결을 다시 맺는다 — **값·조건은 미확인**)
- 사이트 단위 재시도: `Dailymotion … initial request failed, retrying with randomized headers`(첫 요청이 막히면 **헤더를 무작위로 바꿔 한 번 더**).
- 지연 타이머: `DelayTimer requires a valid strand executor`, 구독 확인 간격 `Invalid subscription delay range: min=…` (**구독 갱신 간격에 최소·최대 범위**가 있다).
- **미상**: YouTube 429 에서 실제로 몇 분 쉬는지·지수 백오프 여부는 문자열로는 안 나온다.

## 5. 큐·동시 다운로드·재개 (관찰)

- 두 겹 큐: `ParseControllersQueue`(정보 해석 대기열) + `SimultaneouslyRunningControllersQueue`(실제로 동시에 도는 것 · 한도 설정 「동시 다운로드」, 무료판은 막고 **Pro 에서 7개까지**라는 안내 문구).
- 상태 이벤트 모델: `ResumeEvent`/`ResumedEvent`/`SubtitleProcessingInfoEvent`/… — UI·저장소가 이벤트를 구독. 큐 로그: `Queue element:%1% was created / was NOT created / failed pre-check / failed post-check / was pended, resume it`.
- **전처리·후처리 검사 함수**(pre-check/post-check)를 큐 항목마다 둔다. 「일시정지→재개」「재시도」 버튼(`Resume All`, `Retry Download`)이 모든 항목에 있다.
- 기타: 시스템 절전 방지 옵션, 속도 제한(재시작하면 초기화), 가져오기/내보내기(다운로드·구독 목록).

## 6. 자막 (관찰)

- 트랙 종류 구분: **일반(Normal) · 자동 생성(Transcribed) · 자동 번역(Translated) · 주석(Annotation) · Any**. 「기본 언어」 메시지 따로(`DefaultSubtitlesLangMessage`).
- 채널·재생목록·검색 결과에서 **자막만 일괄 받기**, 영상에 **자막 삽입(embed)**. 무료판은 일괄 자막 갯수 제한 알림(`showBatchSubtitlesLimitNotification`).

## 7. 구독(채널·재생목록 자동 받기) (관찰)

- 채널 구독 = 처음에 **기존 영상 전부 + 이후 새 영상 자동 받기**를 고름. 갱신 주기 설정(Pro). 항목별 변경 감지 로그(제목·썸네일·마지막 추가 시각·안 본 개수 변경)를 SQLite 에 기록해 **변한 것만 갱신**.
- 채널 영상 일부만 저장했을 때 「나머지도 받을까요?」 안내.

### 가져오지 않을 것 (판단)
- **PO token 을 직접 생성하는 숨은 웹엔진 BotGuard 실행**: 유튜브의 봇 방지 장치를 앱이 돌파하는 구조다. 유튜브 정책·그룹 계정 위험이 크고(「관련 채널」 연쇄 정지 전례), 유지 비용이 높다 → **제외**. yt-dlp 가 지원하는 범위에서만.
- 14개 InnerTube 클라이언트 흉내·서명 해독 자체 구현: yt-dlp 가 이미 한다. npm 의존성·유지 부담 증가(⛔ 의존성 늘리지 않기 원칙).
- 다른 사이트 파서(Bilibili·Twitch 등): Priming 용도(영상 자료 참고) 밖.
