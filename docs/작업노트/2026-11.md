## 📬 Gmail 연결 만료(invalid_grant)를 알아보고 안내 (2026-11-03, v1.0.12)
- 로이 실사용: 첫 화면 단추가 「Gmail 연결 오류 (invalid_grant) — Gmail API 활성화·권한·계정 연결을 확인하세요」. 저장된 연결로 토큰 갱신을 직접 시험 → Google 답 `400 invalid_grant · Token has been expired or revoked.`
- 원인(사실 + 추론): 출판 메일 OAuth 클라이언트(프로젝트 `442663560304` · 유튜브 업로드 프로젝트와 별개)가 동의 화면 「테스트」 상태로 만들어졌다(옛 연결 안내도 「테스트 사용자」). 테스트 앱은 refresh token 이 7일 뒤 만료된다. 발송 기록(KST): 10-17·10-22·10-23 → (10-23 밤 만료 추정 → 다시 연결) → 10-27·10-29·10-30·11-02 → 11-03 오후 만료 — 7일 주기와 맞는다.
- 고침: `gmail-client.token()` 이 `invalid_grant` 면 죽은 토큰을 지우고 `expiredAt` 을 남긴다(메일 주소는 유지) → `status().expired` · 오류 문구 「Gmail 연결이 만료됐습니다 — ⚙ 설정 → 👤 계정 탭에서 「Google 로그인」으로 다시 연결하세요」 · 다시 연결하면 풀림 · 다른 오류는 연결을 끊지 않는다. 화면: 회신 칸이 오류 뒤 상태를 다시 읽어 「만료」 안내 · 계정 탭에 만료 경고 · 연결 안내 문구를 「프로덕션으로 게시」로(「테스트 사용자」 안내 삭제).
- 근본 해결은 로이 몫: Google Cloud 프로젝트 `442663560304` OAuth 동의 화면 → 「프로덕션으로 게시」 → 한 번 다시 연결(「확인되지 않은 앱」 경고는 고급 → 이동).
- 시험: `test:bookmail` — 실제 클라이언트에 Google 의 invalid_grant 응답을 넣어 만료 처리·다시 연결(옛 코드면 실패) · E2E 계정 탭 만료 안내 · `test:makeall` 28/28.

- 원인: `book-mail-auto` 는 **열린 원고**의 제목으로 메일을 고른다 — 원고를 먼저 열어야만 쓸 수 있었다.
- **새 IPC `book-mail-inbox`**(`core/book/resubmit-ipc` · 출판 첫 화면 「📬 부크크 메일 확인해서 판권 고쳐 회신」): 부크크 「판권지수정요청」 메일(최근 60일) 먼저 → 헤더 채널(출판)의 원고 폴더에서 `.md` 첫 `# 제목` 줄을 읽어(`core/book/script-find` · `_`/`.` 폴더 제외 · 읽기 전용) 메일 꼬리표의 책과 맞춘다(`requestOf` 그대로) → **답하지 않은 메일이 있는 책만** 「원고 열기」와 같은 `openBookPaths` 로 연다 → 기존 자동 처리(`runAuto` — 옛 `auto` 본문을 함수로 뺀 것 · 멈춤 조건 그대로)로 판권 입력 → PDF → 회신.
