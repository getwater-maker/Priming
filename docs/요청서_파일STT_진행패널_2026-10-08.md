# 요청서 — 🎧 파일 STT(전사)에도 진행 패널 (2026-10-08 · wise-priming 세션 → 프라이밍 세션)

## 무엇을
파일을 골라 전사하는 **🎧 STT**(`main.js` 의 `ipcMain.handle('stt-transcribe')`)에도, **🔗 URL 받아 전사**에 이미 있는 **진행 패널**(v0.5.22, 작업노트 2026-09 「URL 받아 전사 — 진행 패널」)을 붙인다.

- 지금은 `🎧 STT 시작: 파일명` → (한참 아무것도 없음) → `STT 완료` 로그뿐이다. 긴 파일(통화 녹음 등)은 돌아가는지 멈췄는지 알 수 없다.
- 패널에 보일 것(URL 패널과 같은 모양 · 받기 줄만 뺀다):
  - 전사 `완료 / 전체 파일 수` · **지금 전사 중인 파일 이름**
  - **청크 진행**(`transcribeToTxt` 의 `opts.onChunk` — URL 쪽이 이미 쓰는 것) · 청크가 1개면 「전사 중」만
  - 경과 시간 · 실패 수·실패 목록 · ⏹ 중단(`_dlAbort` · ⛔ `S.abort` 쓰지 말 것) · 끝나면 닫기
  - ⚠ 남은 시간 어림은 넣지 않는다 — URL 패널과 같은 이유(전사는 길이에 따라 달라 추정이 거짓말이 된다). 단, 청크 수를 알면 「청크 n/N」은 정직한 진행률이다.
