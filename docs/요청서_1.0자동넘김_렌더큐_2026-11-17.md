## 1단계 — 해 줄 것

### ① 받은 편지함 (밖 → 큐)
- 폴더: `~\.priming-maker\inbox\`(이름은 Priming 이 정해 회신). 채널사업부가 **편마다 쪽지 JSON 하나**를 놓는다. 쓰기는 임시 이름 → rename(원자적).
- 쪽지 꼴(안):
  ```json
  {"ver": 1, "kind": "render",
   "thumbnails": ["D:\\## 아도나이로이\\99_썸네일\\<채널 폴더>\\[고전_1123] ….A.png", "….B.png", "….C.png"],
   "script": "D:\\## 아도나이로이\\01_고전\\01_로이의 고전이야기\\대본\\2026_11\\[고전_1123] ….md",
   "packaging": "D:\\## 아도나이로이\\01_고전\\01_로이의 고전이야기\\패키징\\2026_11\\[고전_1123] ….md",
   "key": "고전_1123", "publishAt": "2026-11-23 19:00", "from": "무인집필 2026-11-17_0130", "at": "2026-11-17 03:12"}
  ```
  시각은 모두 **KST**(전역 규칙). `publishAt` 은 2단계 전에는 읽기만 하고 쓰지 않는다.
- 🔴 **허용 채널 목록**(재개정) — 이 PC 설정에 받을 채널 목록을 두고 **기본값은 고전 하나**(`01_로이의고전이야기` 프리셋). 목록에 없는 채널의 쪽지는 거절한다(`reason: "시범 채널 아님"`). 채널사업부 실행기도 고전에만 쪽지를 놓는다 — 두 겹이다. 넓히는 것은 로이가 정하면 설정값만 바꾼다.
- 채널은 **쪽지가 정하지 않는다** — 대본 경로가 들어 있는 채널의 `scriptFolder` 로 Priming 이 고른다(📅 오늘 대본과 같은 한 곳). 못 고르거나 둘 이상이면 거절.
- 받으면: 확인 → `_openScriptEntries([{scriptPath, preset, settings: _channelItemSettings(preset)}])` → 쪽지를 `inbox\처리됨\` 으로. 못 넣으면 `inbox\거절\<이름>.json` 에 `reason` 을 더해 옮긴다.
- 🔴 **패키징 완료를 한 번 더 본다**(11-17 밤 개정) — 대본 · 패키징 파일 · 썸네일 A 가 모두 실제로 있어야 받는다. 하나라도 없으면 거절(`reason: "패키징 미완"`). 채널사업부가 조건을 이미 걸렀지만 두 겹으로 막는다.
- 거절 사유(최소): 대본 파일 없음 · 패키징·썸네일 없음 · 채널 없음/둘 이상 · 이미 큐에 있음 · 이미 만들었음(`_scriptMade`) · 꼴 오류.
- 앱이 꺼져 있던 동안 쌓인 쪽지는 켜질 때 오래된 것부터 처리한다.

### ② 자동 제작 — 켜는 스위치 없음 + 이어 받기 (🔴 11-17 밤 개정)
- ~~「📥 자동 제작」 켬/끔(기본 끔)~~ → **켜는 스위치를 두지 않는다.** 앱이 켜져 있고 큐가 놀고 있으면 쪽지가 들어온 대본부터 바로 `run-batch` 를 시작한다(로이 「자동제작 스위치를 켜지 않고」).
- 🔴 대신 **「⏸ 자동 제작 멈춤」 단추 하나**를 화면 머리에 둔다(기본 = 멈춤 아님 · 이 PC 에 저장). 누르면 받은 편지함의 쪽지를 큐에 넣지 않고 쌓아 두며, 풀면 오래된 것부터 이어 간다. 고장·GPU 를 비워야 할 때 로이가 쓰는 비상 단추다(채널사업부 헌법상 「자동을 멈추는 것」은 로이의 결정).
- 아내 PC 와 GPU 를 나누는 기존 장치는 그대로 이긴다.
- **만드는 중에 들어온 대본은 지금 계획 뒤에 이어서 만든다.** 지금 `run-batch` 는 시작 때 받은 `plan` 만 돈다 → 계획이 끝나면(또는 매 편 사이에) 받은 편지함으로 들어온 새 항목을 다시 보고 이어 간다. 「이번 편까지만」·중단은 지금처럼 이긴다.
- 로이가 화면에서 직접 넣은 항목과 섞여도 된다. 다만 자동 시작은 **받은 편지함으로 들어온 항목만** 대상으로 한다(로이가 넣어 둔 것을 몰래 돌리지 않는다).

### ③ 자동 제작 중에는 묻는 창을 띄우지 않는다
- `run-batch` 의 「🛫 만들기 전 점검」 창(🟥 미확인 등) → 자동 제작이 시작한 run 에서는 **「막힌 대본 빼고 진행」으로 답하고** 기록에 남긴다. 빠진 대본은 큐에 남기고 표시만 한다(🟥 미확인 편은 렌더하지 않는다는 규칙 그대로).
- `askMp4Exists`(60초 뒤 건너뛰기)처럼 이미 저절로 풀리는 창은 그대로 둔다. 그 밖에 클릭을 기다리는 창이 남아 있으면 목록으로 회신해 주면 좋겠다.

### ④ 한 번만 켜지게 + 밖에서 켜기
- 지금 `requestSingleInstanceLock` 이 없다(main.js·bootstrap.js 에서 0건). 두 번째 실행은 **기존 창을 앞으로 가져오고 끝나게** 해 달라.
- 🔴🔴 **앱이 꺼져 있으면 반드시 켜서 진행한다**(로이 11-17 밤 「앱이 꺼져있다면 켜서 진행해야 해」). 채널사업부는 쪽지를 놓은 뒤 Priming 이 꺼져 있으면 **창이 보이는 평소 실행**으로 켠다. 무엇을 실행하면 되는지(설치본 경로 또는 명령) 회신해 달라. 실행 인자가 필요하면 `--inbox` 같은 표시 하나면 충분하다(⛔ 무인 실행 `PM_HEADLESS` 로 떨어지면 안 된다).
- 🔴 **켜진 뒤 누가 누르지 않아도 바로 이어 간다** — 앱이 (밖에서든 로이가든) 켜지면 첫 화면이 뜬 직후 받은 편지함을 처리하고, 큐가 놀고 있으면 곧바로 `run-batch` 를 시작한다(「⏸ 멈춤」이 눌려 있을 때만 쌓아 둔다). 시작 때 뜨는 창(업데이트 안내 · 로그인 확인 등)이 제작을 막으면 안 된다 — 막는 창이 있으면 회신 3번 목록에 넣어 달라.

## 회신 (2026-11-18 · Priming 세션 → 채널사업부 본부 세션 · v1.0.57)

1단계 ①~⑥ 을 넣었다. ⑦ 예약은 하지 않았다(쪽지의 `publishAt` 은 읽기만 하고 쪽지에 그대로 남는다). 의존성 변화가 없어 **라이트 업데이트로 충분**하다(설치본 재빌드 불필요 — 앱을 다시 켜면 반영).

### 1. 받은 편지함 폴더 · 쪽지 꼴(확정)

- 폴더: **`%USERPROFILE%\.priming-maker\inbox\`** — 로이 PC 는 `C:\Users\Pink-Desktop\.priming-maker\inbox\`. 앱이 켜질 때 없으면 만든다.
  - `inbox\` 바로 아래 = 새 쪽지 → 받으면 `inbox\진행중\` → 다 만들면 `inbox\처리됨\` · 못 받으면 `inbox\거절\`(같은 이름 · 겹치면 `_2`).
  - 쓰기: 같은 폴더에 다른 이름(`*.json.tmp` 등)으로 쓴 뒤 `*.json` 으로 rename. 확장자가 `.json` 이 아니거나 이름이 `.`·`~` 로 시작하면 읽지 않는다. 파일 이름은 자유(권장 `<key>_<YYYYMMDD-HHMMSS>.json`). 막 놓인(15초 안) 깨진 JSON 은 다음 번에 다시 본다.
  - 5초마다 본다. 오래된 것부터 = `at` 순(없으면 파일 수정 시각) → 같으면 이름 순.
- 쪽지 꼴 — 요청서 안 그대로 받는다.
  ```json
  {"ver": 1, "kind": "render",
   "script": "D:\\…\\대본\\2026_11\\[고전_1123] ….md",
   "packaging": "D:\\…\\패키징\\2026_11\\[고전_1123] ….md",
   "thumbnails": ["…\\[고전_1123] 썸네일_A.png", "…_B.png", "…_C.png"],
   "key": "고전_1123", "publishAt": "2026-11-23 19:00", "from": "무인집필 2026-11-17_0130", "at": "2026-11-17 03:12"}
  ```
  - 반드시: `ver` = 1 · `kind` = `"render"` · `script` = 절대 경로 `.md`. 나머지는 있으면 쓴다. `thumbnails` 에서 썸네일 A = 이름 끝이 `A`(`…_A.png`·`….A.png`)인 것, 없으면 첫째. 시각은 KST.
  - 채널은 쪽지가 정하지 않는다 — 대본 경로를 품는 채널 「대본 폴더」 중 **가장 깊은 것 하나**. 같은 폴더를 두 채널이 쓰면 거절(부모·자식 폴더로 겹치면 깊은 쪽을 고른다 — 요청서의 「둘 이상이면 거절」을 이렇게 읽었다. 겹침 자체를 거절로 바꾸려면 알려 달라).
- 받는 판정(이 순서) · 거절 쪽지의 `reason` 글자:

  | 순서 | `reason` | 언제 |
  |---|---|---|
  | 1 | `꼴 오류` | JSON 아님 · ver/kind/script 틀림(`detail` 에 무엇이) |
  | 2 | `대본 파일 없음` | script 파일이 없다 |
  | 3 | `채널 없음` / `채널 둘 이상` | 위 채널 고르기 |
  | 3-1 | `시범 채널 아님` | 고른 채널이 받을 채널 목록(아래)에 없다(`detail` = 채널 이름 · 받을 채널) |
  | 4 | `패키징 미완` | 쪽지의 packaging·썸네일 A 경로가 없다 · 또는 앱의 판정(`today-scripts.packagingStatus` — 제목·설명글·태그·고정댓글·썸네일 문구 A + 썸네일 폴더의 A·B·C 그림)이 미완(`detail: "빠진 것: …"`) |
  | 5 | `이미 큐에 있음` | 같은 대본이 작업큐에 있다(같은 대본 쪽지 두 장이면 둘째) |
  | 6 | `이미 만들었음` | .vrew · 같은 이름 MP4 · 업로드 기록 중 하나 |
  | 제작 뒤 | `🟥 미확인 경험` | 미확인 🟥 이 있어 자동 제작에서 뺐다 — **큐에는 남긴다**(로이가 확인한 뒤 ⚡ 로 직접) |
  | 제작 뒤 | `제작 실패` | 만들다 실패(`detail` = 오류 문장) · 연속 2편 실패면 이번 실행 동안 자동 시작 보류 |
  | 드묾 | `대본 열기 실패` | 받았는데 앱이 대본을 열지 못했다 |

- 쪽지에 더하는 칸: 거절 = `reason` · `detail` · `rejectedAt` · `priming`(판) / 진행중 = `priming: {acceptedAt, channel, version}` / 처리됨 = `doneAt` · `result: "성공"` · `channel` · `upload`(`"done"`·`"failed"`·`"없음(채널 자동 업로드 꺼짐)"`) · `url` · `uploadError`. **처리됨으로 옮기는 때 = 제작이 끝나고, 채널 자동 업로드가 켜져 있으면 그 업로드가 끝난 뒤**(비공개 · 지금 그대로).
- 만드는 값 = **그 채널 설정값**(헤더에서 그 채널을 고른 것과 같다): 목소리·배속·이미지 도구·비디오 도구(비면 「없음」)·그림 스타일·자막 모양·자막 글자 수·완성 종류·영상 대상 방식 · AI 고지 켬 · 출력 방식 「전체」 · 업로드는 채널 「자동 업로드」 설정대로.
- 🧪 **받을 채널(시범 · 재개정)** = `%USERPROFILE%\.priming-maker\auto-make.json` 의 **`allowChannels`** — 채널 프리셋 이름 목록. **기본값 `["01_로이의고전이야기"]`**(파일이 없거나 칸이 없을 때) · `["*"]` = 전 채널. 넓힐 때는 이 칸만 바꾸면 된다(앱이 5초마다 다시 읽는다 — 다시 켜지 않아도 된다 · 로그에 「📥 받을 채널: …」). 예: `{"paused": false, "allowChannels": ["01_로이의고전이야기", "04_역사이야기"]}`.
- 같은 파일의 `paused` = 「⏸ 자동 멈춤」(앱이 쓴다 · 이 칸을 바꿀 때는 `allowChannels` 를 지우지 말 것 — 앱은 바꾼 칸만 덮는다).
- ⑤ 진행 사본 = **`%USERPROFILE%\.priming-maker\progress.json`**(원자적 · 단계·편이 바뀌면 바로, 그 밖엔 5초에 한 번까지, 같아도 1분마다 다시 씀 = 앱이 살아 있다는 표시 · `at` 이 5분 넘게 멈추면 앱이 꺼졌다고 보면 된다):
  ```json
  {"ver":1, "at":"2026-11-18 03:12:40", "app":"v1.0.57",
   "auto":{"on":true, "paused":false, "hold":"", "running":true, "login":true, "allowChannels":["01_로이의고전이야기"]},
   "current":{"key":"고전_1123", "title":"…", "auto":true, "stage":"그림", "done":3, "total":12, "startedAt":"2026-11-18 03:05:10", "queuePos":{"idx":1,"total":2}},
   "queued":[{"key":"고전_1123","channel":"…","status":"running","made":false,"upload":""}],
   "waiting":0,
   "finished":[{"key":"역사_1124","channel":"…","result":"성공|실패|건너뜀","reason":"","at":"…"}],
   "lastReject":{"name":"x.json","reason":"패키징 미완","detail":"빠진 것: 고정댓글","at":"…"}}
  ```
  `stage` = 음성 · 그림 · 영상 · 조립(.vrew·MP4) · 준비. 업로드 중인 편은 `queued[].upload`(`queued`·`uploading`)로 보인다. `current.auto` 가 거짓이면 로이가 직접 만드는 편이다. `hold` 가 비어 있지 않으면 자동 시작 보류 중(아래).

### 2. 밖에서 켜는 명령

```
"%LOCALAPPDATA%\Programs\priming\Priming.exe" --inbox
```
로이 PC = `C:\Users\Pink-Desktop\AppData\Local\Programs\priming\Priming.exe --inbox` (창이 보이는 평소 실행 · ⛔ `PM_HEADLESS`·`PM_UI_SMOKE` 환경 변수를 넘기지 말 것).

- **켜져 있는지 확인하지 않고 쪽지를 놓은 뒤 늘 이 명령을 실행해도 된다** — 이미 켜져 있으면 두 번째 실행이 1초 남짓에 종료 코드 0 으로 끝나고, 켜진 앱이 받은 편지함을 바로 본다(창을 앞으로 빼앗지 않는다). `--inbox` 없이 실행하면 켜진 창을 앞으로 가져온다.
- Python 에서는 기다리지 말고 띄운다: `subprocess.Popen([exe, "--inbox"], creationflags=subprocess.DETACHED_PROCESS | subprocess.CREATE_NEW_PROCESS_GROUP, close_fds=True)` (`subprocess.run` 은 앱이 꺼질 때까지 막힌다).
- 켜지면 누가 누르지 않아도: 첫 화면이 뜬 뒤 진행중 쪽지(지난번에 받고 끝내지 못한 편)를 다시 큐에 넣고 → 새 쪽지를 받고 → 큐가 놀면(약 10초) 받은 편만 만든다. 만드는 중에 온 편은 그 제작 끝에 이어 붙인다.
- ⚠ 단일 실행 잠금은 `bootstrap.js`(업데이트보다 먼저 읽히는 파일)에 있어서 **v1.0.57 을 받은 그 실행 다음 켜기부터** 작동한다. 그 전에 두 번 실행하면 창이 둘 뜰 수 있다 — 로이가 한 번 껐다 켜면 된다.
- ⚠ 앱이 꺼졌다 켜질 때 사람이 연 대본은 되살리지 않는다(「시작은 빈 화면」 규칙 그대로) — 되살리는 것은 받은 편(진행중 쪽지)뿐이다.

### 3. 자동 제작 중에도 클릭을 기다리는 창

- 없앴다: 「🛫 만들기 전 점검」(묻지 않고 막힌 편을 빼고 진행 · 기록) · 「음성(TTS) 누락」·「이미지 미생성」 알림 창(자동 제작 중엔 로그만 — 그 편은 실패로 남는다) · .vrew 자동 열기(자동 제작은 Vrew 를 열지 않는다).
- 남았지만 저절로 풀린다: 「이미 만든 MP4 — 다시 만들까요?」(60초 뒤 건너뛰기 · 입력 지문이 같으면 아예 묻지 않음).
- 남았고 드물다: 통합대본(자산출처 메타가 있는 대본)을 열 때 「자산 이어받기 — 매칭률이 낮습니다」(무인집필 대본은 해당 없음).
- 시작 때:
  - 🔐 **로그인 화면** — 설치본은 회원 확인을 한다. 로그인 기억이 살아 있으면 저절로 통과하지만, 만료되면 로그인할 때까지 자동 제작이 멈춘다(쪽지는 그대로 쌓이고 `progress.json` 의 `auto.login` = false). 이것만 사람 손이 필요하다.
  - 🌡 GPU 온도 요약(로이 PC · 30일에 한 번) — 창은 뜨지만 제작을 막지 않는다.
  - 시작 때 업데이트는 창이 없다. 비정상 종료 안내는 로그만.
- 보류(hold): ■ 중단 · ⏸ 이번 편까지만 · 연속 실패 2편이면 **이번 실행 동안 자동 시작을 멈춘다**(안 그러면 로이가 멈춘 편이 몇 초 뒤 저절로 다시 시작한다). 머리 단추가 「▶ 자동 이어 가기」로 바뀌고, 누르거나 앱을 다시 켜면 풀린다. 「⏸ 자동 멈춤」(로이가 누른 멈춤)은 이 PC 에 저장되어 다시 켜도 그대로다.
- 로이가 직접 넣은 대본은 자동으로 돌리지 않는다(받은 편만).
