## 2. ⚠ 함정 — 「바탕 + 글자」는 캔바본과 똑같지 않다
캔바 완성본에는 템플릿 층(정보·일본의 그라데이션 그림 2장, 다산의 어둡게 까는 층, 크롭·반전 등)이 더 얹힌다. 길 둘:
- **① 편집기가 채널별 덮개 층을 재현** — 채널마다 다르고 규약이 바뀌면 어긋난다(유지비 큼).
- **② 캔바에서 글자만 숨긴 「글자 없는 완성 배경」을 `99_썸네일\<채널폴더>\_배경\[약칭_MMDD] 썸네일_A_배경.png`(안마다)로 같이 내보내게** 채널사업부 무인 캔바 단계를 바꾼다(그쪽이 가능하다고 함 · **로이 승인 사안**). 편집기는 이 배경이 있으면 그것을, 없으면 Codex 바탕(+ 채널 어둡게 층 1장 정도의 단순 보정)을 쓴다.
- 🔑 추천 = **② 먼저, ① 은 하지 않는다**(편집기를 단순하게 · 두 곳 규약이 갈라지지 않게).

## 3. 편집기가 하는 일 (1단계)
1. 편 선택 → A/B/C 한 화면(로그 상자 🖼 탭의 썸네일에서 「✏ 수정」으로 진입).
2. 배경 위에 헤드라인 글상자: 줄마다 글·색(흰/노랑) · **모든 줄 같은 크기**(디자인원칙 — 글자 크기 한 값) · 굵은 글꼴 + 검은 외곽선 · 9칸 중 왼쪽·가운데 6칸 자리 선택 + 끌어 옮기기.
3. 얼굴 가림 경고·자동 추천 자리: `core/info-theme` 의 살색 덩어리 거부권을 재사용(⚠ 색 기반이라 부정확 — 경고만, 막지 않음).
4. 규격 검사(1280×720 · 2MB 이하 · 파일명)와 내보내기.
5. 문구 대조: 편집기 줄 목록 == 패키징 `문구뽑기` 그 안 줄 목록. 다르면 **「로이 수정」** 으로 표시.

## 4. 파일 약속
- 프라이밍이 **쓰는 곳** = `99_썸네일\<채널폴더>\` 의 편집기 내보내기와 `_캔바원본\`(원본 보존) · `<채널>\썸네일\`(바탕)·패키징·`_미확정\` 은 **읽기만**.
- **덮어쓰기**: 하류(Studio 예약 절차 · 대시보드 · `썸네일배치.py 규격`)가 `[약칭_MMDD] 썸네일_A.png` 이름 하나만 본다 → **내보내기 전에 기존 파일을 `_캔바원본\` 으로 옮겨 보존하고 원래 이름으로 저장**(원본을 지우지 않는다 · 같은 이름이 이미 `_캔바원본\` 에 있으면 `_2` 로 비켜 보존 · `P.claimPath` 규칙). `_수정` 접미사 방식은 「어느 쪽이 진짜냐」가 생겨 쓰지 않는다. (로이 결정)
- **사이드카** `[약칭_MMDD] 썸네일_문구.json`(제안 형식): `{편, 캔버스, 안:{A:{줄:[{글,색}], 크기, 자리, 글꼴, 캔바디자인?, 로이수정?}}}` — 편집기가 내보낼 때 씀. 채널사업부 무인 캔바 단계도 같은 형식으로 쓰게(로이 승인 뒤).
- **패키징 .md 는 프라이밍이 고치지 않는다**: 로이가 문구를 바꾸면 사이드카에 `"로이수정": true` — 채널사업부가 읽어 패키징을 맞춘다(다른 저장소 파일은 그 세션이 고친다).
- 폴더·파일 이름 규칙을 바꾸면 상대에게 요청서로 먼저 알린다.

## 5. 프라이밍 코드 쪽
- 새 파일: `core/thumb-edit.js`(문구 읽기 · 배치 계산 · 규격 검사 · 사이드카 — 순수 함수) · `renderer/src/ThumbEditor.jsx`(캔버스 미리보기 + 내보내기는 렌더러 캔버스 → PNG 바이트를 main 이 `writeFileAtomic` 로 저장).
- 글꼴: 앱에 있는 Pretendard Bold · Noto Sans JP 로 시작. **새 한글 굵은 글꼴 동봉은 로이 승인 필요**(규칙) — 캔바 템플릿 글꼴과 같아야 거의 똑같아 보인다(`글꼴` 값 = 사이드카).
- 업로드 마무리(`core/yt-finish` 썸네일 A)가 읽는 파일 = 같은 원래 이름이라 따로 안 고쳐도 된다(확인 필요).
- 시험: 순수 계산 단위 시험 + E2E(임시 폴더 · 로이 진짜 `99_썸네일` 에 쓰지 않음).
