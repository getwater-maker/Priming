# 요청서 — 🌙 모니터 끄기 후 저절로 다시 켜짐 (2026-09-27 · 쓰레드 세션 → Priming)

## 무엇을
「🌙 모니터 끄기」(main.js `monitor-off`, v0.5.80)로 끈 뒤 **아무도 안 건드렸는데 화면이 한 번 켜진다.** 밤에 자다가 밝아져 놀란다(로이).
Windows 자체 절전으로 꺼질 때도 똑같이 "꺼짐 → 한 번 켜짐 → 그대로 두면 다시 꺼지고 그 뒤로는 유지"가 된다.

## 사실 (Windows 이벤트 로그 · System · Kernel-Power 566, 2026-09-26~27)
- 저절로 켜진 모든 경우가 **`MonitorReason=32`(마우스 입력)** 이고, **꺼진 지 136.4~137.3초 뒤**로 거의 같다(6회 전부).
  사람이 직접 깨운 경우는 `31`(키보드)이고 간격이 제각각이다.
- 시스템 절전은 없었다(`powercfg /lastwake` 0) — 화면만 꺼졌다 켜진 것.
- 마우스는 Logitech 수신기(046D:C534)가 메인보드 USB 에 직접 꽂혀 있다(모니터 허브 아님).
- 모니터 3대: 주모니터 DISPLAY1 2560×1080(ULTRON 3547UC, **DisplayPort**) · TFG22F14T 2대(하나 **DisplayPort**, 하나 **HDMI**). 커서는 평소 주모니터 위에 있다.

## 판단 (가설 · 확신도 중상 — 실측 확인 중)
시간이 매번 같다 = 손이나 마우스 떨림이 아니다. **DisplayPort 모니터가 신호가 끊긴 지 약 2분 뒤 깊은 절전에 들어가며 PC 에서 "빠진다"** →
Windows 가 화면 배치를 다시 잡으며 **그 모니터 위에 있던 커서를 다른 모니터로 옮긴다** → 이 이동이 마우스 입력으로 잡혀 화면이 켜진다.
두 번째로 꺼질 때는 커서가 이미 남는 모니터로 옮겨져 있어서 다시는 안 켜진다 — 로이가 본 "한 번만 켜진다"와 맞는다.
- 확인 중: 쓰레드 세션이 1초 간격으로 모니터 개수·커서 위치를 기록 중(`...\scratchpad\displog.txt`, 09-27 15:43부터 10시간).
  켜지는 순간 `screens=3→2` 와 커서 좌표 점프가 보이면 확정이다.

## 고칠 곳 제안 — main.js `monitor-off`
1. **끄기 직전 커서를 HDMI 모니터(빠지지 않는 쪽)로 옮긴다** (`SetCursorPos` — 같은 PowerShell 블록에 user32 P/Invoke 한 줄).
   어느 모니터가 HDMI 인지는 `WmiMonitorConnectionParams.VideoOutputTechnology`(5=HDMI, 10=DP)로 고르고, 없으면 현재 방식 그대로.
2. **보험**: 끈 뒤 6분 동안 화면 개수가 바뀌거나 키보드 입력 없이 켜지면 한 번 더 끈다(여기까지는 짧은 번쩍임이 남는다 — 1번이 본 해결책).
3. 작업노트에 경위를 남긴다.

## 로이 쪽 대안 (코드 없이)
DP 모니터 OSD 에 「DP 깊은 절전 / 자동 전원 끄기 / Deep Sleep」 같은 항목이 있으면 끄면 모니터가 빠지지 않는다(모델마다 이름이 다르다).
