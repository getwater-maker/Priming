## 1. 대본 .md 저장이 원자적이지 않다 (P0 — 저장 중 꺼지면 대본이 깨질 수 있다)

**무엇이 문제인가**
문장 편집·합치기·나누기 등이 대본 .md 를 `fs.writeFileSync(S.scriptPath, …)` 로 **제자리에서 바로 덮어쓴다.**
쓰는 도중 앱이 죽거나 전원이 나가면(또는 G: 구글드라이브가 순간 언마운트되면) .md 가 비거나 중간까지만 남는다.
대본 .md 는 작업의 정본이라 깨지면 되돌릴 곳이 없다(작업본 `.smproj` 는 이미 임시파일→rename 으로 쓴다).

**어디서** (`main.js` · grep `writeFileSync(S.scriptPath` / `writeFileSync(sp`)
- 8903 · 9117 · 9246 · 9406 · 9717 · 9919 · 10014 · 10108 · 10195 · 10609 · 10736 · 10847 · 11793 — **13곳**
- 대조: 2994 줄(`대본 표시 줄 쓰기`)은 이미 `tmp` 에 쓰고 `renameSync` 한다 → 같은 저장소 안에 올바른 예가 있다.

**제안** (판단은 원본 몫)
- 대본 쓰기 함수를 **한 곳**으로 모은다(예: `writeScriptAtomic(sp, text)` = 같은 폴더 `.tmp` 에 쓰기 → `renameSync`).
  G: 경로는 `P.retryFs` 로 감싼다(2994 줄과 같은 방식).
- 13곳을 그 함수로 바꾸고, 「`writeFileSync(` 로 대본 경로에 직접 쓰는 곳 0개」를 소스 검사 테스트로 묶는다
  (CLAUDE.md §8 「같은 일을 하는 코드가 여러 곳」 단골 사고).
- 주의: `fs.watch`/1.5초 stat 감시(`checkExternalScriptChange`)가 rename 을 「밖에서 바뀜」으로 오인하지 않는지 확인.

**확인 방법**
- 소스 검사 테스트(직접 쓰기 0곳).
- 쓰기 함수에 큰 문자열을 넣고 쓰는 도중 프로세스를 죽였을 때 원래 .md 가 그대로인지.
- `test:makeall` · 대본 편집 E2E 통과.

## 2. SRT 자막이 막간 쉼을 빼고 시각을 계산한다 (P0 — 쉼을 켠 채널은 SRT 가 영상과 어긋난다)

**무엇이 문제인가**
`core/pipeline.js` `writeSrt`(1117 줄)는 문장 시각을 `ttsDurationSec` 누적으로만 낸다.
`.vrew` 빌드는 ⏸ 막간 쉼(채널 `interludePauseSec` · 카드 칸 `쉼=`)만큼 그 문장 음성 뒤에 무음을 덧대므로,
**막간이 하나 지날 때마다 SRT 가 N초씩 앞당겨진다.**
CLAUDE.md §7 R4 는 「시각을 계산하는 곳은 모두 `P.pausePlanOf` 를 거칠 것」이라고 정해 두었는데, `writeSrt` 만 빠져 있다
(화면 카드 2935 · 정보 카드 2949 · DTO 3056 은 이미 거친다).

**어디서**
- `core/pipeline.js` 1117~1137 `writeSrt(project, srtPath, maxChars)` — preset 을 받지 않는다.
- 호출: `main.js` 3610(export-vrew) · 8048(make-all 4단계) — 두 곳 다 preset(`preset` / `ep`)이 손에 있다.

**제안** (판단은 원본 몫)
- `writeSrt(project, srtPath, maxChars, preset)` 로 넓히고 안에서 `pausePlanOf(project, preset).map` 을 읽어,
  쉼이 붙은 문장은 `t += dur + pauseSec` (자막 표시 끝은 음성 끝 `t + dur` 그대로 — 쉼 동안은 자막 없음).
- 두 호출부에 preset 을 넘긴다. 쉼 계획이 없으면 결과가 지금과 **한 글자도 다르지 않아야** 한다.

**확인 방법**
- 막간 쉼 2초 카드 2개를 둔 대본 → SRT 마지막 자막 시작 시각이 .vrew 의 같은 문장 시각과 같은지(4초 차이가 사라지는지).
- 쉼 없는 대본은 SRT 바이트가 전과 같은지(A/B).
- `test:pause` 에 SRT 단언 추가.

## 4. 문장을 빈 글로 지우면 `edit-sentences` 가 깨진다 (P1 — 화면에서 문장 지우기가 오류로 끝난다)

**무엇이 문제인가**
화면에서 클립 글을 모두 지우고 확정하면(「이 문장을 대본에서 지울까요?」 → 확인) `api.editSentences({ …, text: '' })` 가 간다.
그룹에 문장이 둘 이상이면 마지막 문장 보호(「그룹의 마지막 문장은 지울 수 없습니다」)를 지나 본문으로 들어가는데,
`plan.newTexts` 가 빈 배열이라 `made` 도 비고, 다음 줄에서 `made[…].id` 를 읽다가
**`TypeError: Cannot read properties of undefined (reading 'id')`** 로 끝난다.

**어디서** (원본 v0.9.88 · `main.js`)
- 9170: `old.forEach((o, i) => mp.set(o.id, made[Math.min(i, made.length - 1)].id))` — `made.length === 0` 이면 `made[-1]` = undefined.
- 같은 함수 안에 `made[0]` 을 가정하는 곳이 더 있을 수 있다(9171 클립 이력 `made.length === 1` 조건은 안전).

**재현** (Lab 에서 원본 main.js 로 확인 · 2026-10-21)
- 문장 2개인 그룹 → `editSentences({ shortsNum: 1, groupNum: 1, sentIdx: 0, count: 1, text: '' })` → 위 TypeError.
- 같은 대본에서 글을 바꾸는 편집(`'첫 문장은 조금. 길게 씁니다.'`)은 정상.

**제안** (판단은 원본 몫)
- `made` 가 비면 그림 범위·오버레이 id 옮기기를 「지워진 문장 → 이웃 문장(같은 그룹의 다음, 없으면 앞)」으로 하거나 건너뛴다.
- 빈 글 편집(= 문장 지우기) 경로의 E2E 를 하나 둔다(문장 2개 그룹 → 하나 지우기 → .md·그룹·음성 확인 · Ctrl+Z).
