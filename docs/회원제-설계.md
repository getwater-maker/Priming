# Priming 회원제 · 오류 로그 설계 (2026-10-15)

> 로이 결정(2026-10-15): **결제 회원만 사용** · 회원 관리는 primingwave.com(wise-priming) · 결제는 카드 붙이기 전까지 **통장 입금** ·
> 음성·그림은 **회원이 자기 API 를 연결(BYOK)** · 저장소 `getwater-maker/Priming` **비공개 동의** · 회원당 **PC 2대** · 오류 로그는 **오류가 나면 자동 전송**.
> 이 문서는 서버(wise-priming)와 앱(Priming)이 함께 지키는 **약속(계약)** 이다. 한쪽을 바꾸면 이 문서부터 고친다.

## 0. 왜 이 순서인가

- **사실**: 지금 저장소가 공개라 업데이트 주소(`raw.githubusercontent.com`)로 누구나 프로그램 전체를 받을 수 있다. 로그인 화면만 붙이면 코드에서 지우면 그만이다.
- 그래서 **업데이트를 회원 확인을 거치는 서버에서만** 받게 하는 것이 회원제의 본체다. 로그인 화면은 그 위에 얹는 것.
- ⚠ **비공개 전환은 맨 마지막**. 먼저 바꾸면 새 업데이트 서버를 모르는 모든 PC(로이 메인·아내 PC)가 업데이트를 못 받는다(404 → 전 PC 업데이트 정지).

### 전환 순서 (반드시 이 순서)
1. **서버**(wise-priming): DB·함수·업데이트 중계(§2~§4) — 공개 저장소에서도 동작하게 만들어 둔다.
2. **앱**(Priming): 로그인·회원 확인·새 업데이트 경로(§5) 발행 — 아직 공개 저장소의 옛 경로로 배포된다. 로이 PC 두 대가 이 판을 받고 **관리자로 로그인**.
3. 두 PC 가 새 경로로 업데이트되는 것을 확인(`update:verify` 를 새 경로로).
4. 그 뒤에 저장소 **비공개** 전환(로이가 GitHub 설정에서 · 또는 로이 승인 뒤 `gh repo edit --visibility private`).
5. 회원용 설치본(`npm run dist`)은 비공개 Release 로 두고 §4 중계로만 내려준다.

## 1. 회원 = 무엇으로 판단하나

- primingwave.com 기존 테이블을 그대로 쓴다: `programs`(slug **`priming-app`** 추가) · `cohort_programs` · `enrollments(status, expires_at)` · `admins`.
- **유효 회원** = `admins` 에 있거나, `enrollments.status='active'` 이고 `expires_at is null or expires_at > now()` 인 기수가 `priming-app` 프로그램에 접근 권한이 있는 사람.
- 통장 입금 단계: 입금 확인 → 관리자 화면에서 등록 + 만료일 입력(지금 관리자 화면으로 가능). 카드 결제는 나중에 같은 `enrollments` 행을 자동으로 만든다(앱은 바뀌지 않는다).
- 가입 때 약관·개인정보 동의는 기존 `user_consents` 를 쓴다. **오류 로그 자동 전송**을 개인정보 처리방침에 적는다(무엇을·얼마나 보관하는지 §6).

## 2. 서버 — DB (wise-priming 마이그레이션)

```
app_devices(user_id uuid → auth.users, device_id text, name text, first_seen timestamptz, last_seen timestamptz,
            primary key(user_id, device_id))
app_error_logs(id bigserial, user_id uuid, device_id text, app_version text, created_at timestamptz default now(),
               kind text check (kind in ('auto','report')), summary text, body text)   -- body ≤ 64KB(앱이 자른다)
```
- 기기 상한 = **2**(설정값 · 회원별 예외가 필요하면 `enrollments` 에 칸을 더한다). 관리자는 상한 없음.
- RLS: 본인 행만 SELECT/DELETE(기기 해제는 사이트 「내 기기」에서) · 로그는 본인 INSERT 만, 읽기는 관리자만.
- 로그 보관 30일(매일 지우는 예약 SQL 또는 Edge Function cron).

### RPC (security definer · 앱은 Supabase REST 로 부른다)
- `priming_license(p_device_id text, p_device_name text)` → `{ ok, member, admin, expires_at, devices:[{device_id,name,last_seen}], reason }`
  - 회원이 아니면 `ok=false, reason='not_member'` · 만료면 `'expired'`.
  - 처음 보는 기기이고 이미 2대면 `ok=false, reason='device_limit'`(목록을 돌려줘 앱이 「사이트에서 기기 해제」를 안내).
  - 통과하면 `app_devices.last_seen` 갱신.
- `priming_log(p_device_id, p_app_version, p_kind, p_summary, p_body)` → 하루 기기당 **30건** 넘으면 버린다(폭주 방지 · 무료 등급 보호).

## 3. 앱 로그인 방식

- **Supabase 이메일·비밀번호 로그인**을 앱 main 에서 REST(fetch)로 — ⛔ npm SDK 추가 금지(라이트 업데이트가 막힌다). 소셜 로그인 회원은 사이트에서 비밀번호를 정하게 하거나, 2단계에서 「브라우저로 로그인」(로컬 주소로 돌아오기)을 더한다.
- 받은 access/refresh 토큰은 `safeStorage` 로 암호화 저장(⛔ 렌더러로 돌려주지 않는다 · 평문 금지 — 기존 자격증명 규칙).
- `device_id` = 처음 실행 때 만든 무작위 UUID(`~/.priming-maker/device.json`) · 이름 = 컴퓨터 이름.
- 앱을 켤 때 `priming_license` 확인. **인터넷이 안 되면 마지막 성공 뒤 7일까지** 그대로 쓴다(그 뒤엔 로그인 화면).
- 회원이 아니면: 로그인 화면 + 「primingwave.com 에서 가입·입금 안내」 링크. 제작 기능은 열지 않는다.

## 4. 업데이트 중계 (저장소 비공개 뒤에도 회원만 받게)

- **Cloudflare Worker**(무료 하루 10만 요청) `updates.primingwave.com`:
  - `GET /manifest` · `GET /file/<경로>` — 헤더 `Authorization: Bearer <Supabase access token>` 를 Supabase 로 확인 + `priming_license` 와 같은 회원 판정 → 통과하면 **비공개 저장소의 raw 파일**을 서버 쪽 GitHub 읽기 전용 토큰으로 받아 그대로 준다.
  - ⛔ GitHub 토큰은 Worker 비밀값에만(앱·저장소·로그에 없음).
  - 설치본(.exe)도 같은 방식(비공개 Release 자산).
- 앱 `light-updater.js`: 주소를 Worker 로 바꾸고 토큰 헤더를 단다. **「전부 받아 해시 확인 → 그 뒤에만 교체」 규칙은 그대로**(`test:updater`). 토큰이 없거나 만료면 업데이트를 건너뛰고 지금 판으로 켠다(⛔ 업데이트 실패로 앱을 막지 않는다 — 회원 확인은 §3 이 한다).
- `update:verify` 도 Worker 경로로 확인하게 고친다(관리자 토큰).

## 5. 앱이 함께 바꿔야 하는 것 (BYOK)

- **로이 전용 기본값을 걷어낸다**: OmniVoice·ComfyUI 기본 주소 `DESKTOP-CBQLOLJ`·Tailscale 이름, 참조음성 서버 동기화, 썸네일 기본 폴더(`D:\## 아도나이로이\…` — 있을 때만 쓰므로 무해하지만 회원 화면엔 안 보이게), 유튜브 업로드 공용 연결 등. → 관리자(로이)일 때만 지금 기본값, 회원은 빈 값 + ⚙ 설정에서 자기 주소·키.
- API 키는 지금처럼 PC 안 `safeStorage`(서버로 보내지 않는다 — 사이트의 BYOK 와 다른 점: 앱은 로컬에서 쓴다).

## 6. 오류 로그 자동 전송

- **언제**: 로그에 오류 줄(`✗`·`❌`·`🐞 화면 오류`·잡히지 않은 예외)이 찍히면 → 60초 모아서 한 번 보낸다(같은 오류 반복은 한 번).
- **무엇을**: 그 오류 앞 **200줄**(그날 로그 파일에서) + 앱 버전 + 기기 id. 64KB 에서 자른다.
- **지우고 보낸다(필수)**: API 키 모양(`sk-…`·`AIza…`·`hf_…`·긴 16진/base64 토막) · 이메일 · 사용자 폴더 경로(`C:\Users\<이름>` → `~`) · 전화번호. 지우는 규칙은 한 곳(`core/log-scrub.js`) + 시험(판정력 포함).
- **수동 보고**: 로그 상자 「🐞 문제 보고」 = 그날 로그 전체 + 회원이 쓴 설명(`kind='report'`).
- 회원이 ⚙ 에서 자동 전송을 끌 수 있다(기본 켬 · 처리방침에 명시).
- **로이가 보는 곳**: primingwave.com 관리자 「Priming 오류」 화면 — 회원·기기·버전·날짜로 거르고 본문을 본다.

## 7. 비용 (무료 등급 안)

- Supabase 무료: DB 500MB — 로그 64KB × 하루 기기당 30건 상한 × 30일 보관이면 회원 수십 명까지 여유. 넘으면 보관일을 줄인다.
- Cloudflare Worker 무료 하루 10만 요청 — 업데이트는 바뀐 파일만 받으므로 충분.
