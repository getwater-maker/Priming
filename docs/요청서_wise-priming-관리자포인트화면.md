## 1. 포인트 「회수」 전용 버튼
- 지금은 「지급」 창에 **음수를 넣으면 조정(차감)** 이 되지만(034 `admin_priming_points_grant`: 잔액보다 크게 빼면 거부) 로이가 이 방법을 알기 어렵다. 회원 행의 `지급` 옆에 **`회수`** 버튼을 둔다 — 창에 「현재 남은 N pt · 회수할 pt」 입력(최대 = 남은 포인트) + 사유 메모 + **확인 문구**(「○○ 계정에서 N pt 를 회수합니다」) → 내부는 같은 RPC 에 음수.
- 원장 내역에 지급·회수를 같은 목록으로 보이고(`kind` · 사유 · 한 관리자) 회수는 붉은 글씨.
- (선택) 아내 PC 처럼 이미 지급한 값을 실수로 준 경우를 위해 「직전 지급 취소」는 만들지 않는다 — 회수로 충분.

## 2. kie 보유 잔액 표시 (회원 포인트 지급 판단용)
- 화면 맨 위(표 위)에 한 줄: **「kie 잔액 N크레딧(≈$M) · 회원 미사용 포인트 합계 K · 여유 N−K」** — 여유가 K 의 20% 아래면 붉게(자동 충전 기준은 로이가 kie 에서 설정).
- 잔액은 kie 의 크레딧 조회 API(읽기 전용)를 **서버가** 부른다 — kie 키는 서버 비밀값(Secret)에만 둔다(브라우저·앱에 두지 않는다 · kie 대행 요청서와 같은 키). 서버 대행이 생기기 전 임시로는 로이가 잔액을 손으로 적는 칸(수동 입력 + 적은 시각)으로 대신해도 된다.
- 참고: 지금 앱(로이 PC)에서는 ⚙ 설정 → 🔑 API 키 → kie 「✔ 검증」이 남은 크레딧을 보여 준다.

## 3. 오류 문구를 진짜 원인으로
- `saveGrant` 가 어떤 실패든 「저장하지 못했습니다. 조정은 남은 포인트보다 클 수 없습니다.」 한 문구만 띄운다(2026-10-18 034 미적용일 때 이 문구 때문에 원인을 못 찾았다). 서버가 준 `error.message` 를 해석해 보여 준다: `Only admins…` = 관리자 권한 없음 · `Adjustment exceeds remaining points` = 회수액이 남은 포인트보다 큼 · `Could not find the function…` = 서버 기능 없음(마이그레이션 필요) · 그 밖은 원문 한 줄.

## 4. 관리자 역할(등급) — 안내와 안 보이는 이유 표시
- 사실(코드 확인 2026-10-18): 역할은 `admins.role` = `moderator`(운영자) · `superadmin`(슈퍼어드민). **역할 변경 UI 는 로그인한 사람이 superadmin 일 때만, 자기 자신 제외** 사용자 편집 창에 나온다(`user-edit-dialog.tsx` `canChangeRole`). 변경 RPC 도 superadmin 전용(010). 그래서 운영자(moderator)로 로그인했거나 자기 자신을 편집하면 칸이 안 보인다 — 로이가 「칸이 사라졌다」고 느꼈다.
- 요청: ① 칸이 안 보일 땐 **이유를 한 줄로** 보여 준다(「슈퍼어드민만 바꿀 수 있습니다」 / 「자기 자신의 역할은 바꿀 수 없습니다」) ② 역할 옆에 **차이 설명**(운영자 = 회원·수강·포인트 관리 · 슈퍼어드민 = 거기에 관리자 역할 부여·박탈) — 실제 권한 차이는 코드 기준으로 정확히 적을 것 ③ 상단 역할 배지가 로그인 계정과 맞는지 확인(스크린샷에서 배지가 사라진 적 있음 — 원인 점검).
